What's New

Fix Other details visibility for single-choice questions

## Summary

Fixes #67.

The generic single-choice UI incorrectly displayed the **Other details** field when both the current selection and `other_text_option` were null.

This change requires a configured `other_text_option` and an exact selection match before displaying the field.

Source bug report: #64

## Behavior

- Consent: **Other details** is hidden.
- Q1 normal option: **Other details** is hidden.
- Q1 `Other / Nyingine`: **Other details** is shown.
- Q1 Other detail remains part of the composed answer.
- Q2 Gender: **Other details** is hidden.
- Existing single-choice navigation and submission behavior is unchanged.

## Implementation

- Added a focused visibility predicate requiring a non-null configured Other option and an exact selection match.
- Updated the single-choice UI to use that predicate.
- Added regression tests for all visibility states.
- Added configuration assertions confirming Consent and Q2 do not define `other_text_option` in both English and Swahili survey configurations.
