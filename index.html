## Summary

Improve the semantic accuracy of Swahili EVAL prompts for **Q11 and Q13**. This PR contains two narrowly scoped question-specific prompt changes and corresponding JVM assertions.

## Changes

### Q11 — Harvest threshold interpretation
- Accept a bag threshold expressed either numerically or in words.
- Accept a clearly stated minimum harvest level at which the respondent would continue using a seed, when that establishes the threshold below which they would switch.
- Request clarification when a stated quantity does not make the continue-versus-switch decision clear.
- Add a focused JVM assertion for the Q11 prompt contract.

### Q13 — Post-harvest maize allocation
- Replace the Q13-specific EVAL prompt with the shorter version validated in a real-model A/B comparison.
- Assess allocation reasons for uses actually mentioned by the respondent, using the original answer and answered follow-ups.
- Do not mark supplied information as missing or require exact quantities when the allocation reasoning is clear.
- Update the Q13 JVM test to assert the new evaluation contract.

## Real-model validation

**Q11 (November 13, 2026):**
- Pixel 9a real-model validation recovered 30/30 outputs in the referenced run.

**Q13 (November 16, 2026):** Same Pixel 9a and Gemma 3n E4B IT int4 inference settings, five runs of the complete fixture for each prompt.

## Scope and limitations

Changes are confined to `survey_config_sw_10.yaml` and `SurveyConfigConditionalNavigationTest.kt`. Shared EVAL rules, FOLLOWUP prompts, routing, parsing, scoring thresholds, and inference configuration are unchanged.

The PR does not resolve all Swahili follow-up wording issues. Missing-point descriptions and generated follow-up wording still need separate quality review.
